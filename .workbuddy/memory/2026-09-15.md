### 滚动条对齐（39ecdad）—— 一个之前完全漏掉的面
**项目此前完全没有滚动条样式**，所有可滚动窗口（我的电脑、记事本、命令提示符、
显示属性）用的都是浏览器默认灰滚动条，而基准是 Luna 蓝色滚动条。
规格在 `css/luna/controls.css` 的 `appcontents ::-webkit-scrollbar` 系列：
- 尺寸 17×17，隐藏箭头按钮
- 轨道 `linear-gradient(to right,#f3f1ec,#fefefb)` + `inset 1px 0 #eeede5` 等
- 滑块底色 `#c9d8fc→#b9cdfb`，多层 inset 阴影，`border 1px solid #fff`，圆角 3px
- 抓手位图：纵向常态用 **scrollgrip_vertical_active.png**（注意基准纵向常态就用 active）、
  悬停用 scrollgrip_vertical_hover.png；横向用 scrollgrip_horizontal.png
- **横向的 hover/active 两个抓手位图爬取副本里没有**，横向这两态以配色变化代替
- 经典主题覆盖为 `#d4d0c8` + 3D 立体滑块

**注意**：CSS 里写 `url(../assets/...)` 是可以的（CRA 的 css-loader 会处理相对路径），
不必像窗口按钮位图那样从 JS 注入。因为这两处的需求不同：
CSS 里能写死的就直接写，需要随主题在 JS 侧切换的才走 CSS 变量注入。

### 写字板（7a02596）
- 放弃了原计划的「磁盘清理」：VFS 整盘文本总量只有 **6762 字符**、目录体积无从取得，
  而磁盘清理的核心就是显示可回收体积 → 用真实数据会难看，编造数字没意义。
  **判断依据：宁可不做，不要伪造数据。**
- 写字板用 `document.execCommand` 实现富文本（加粗/斜体/下划线/对齐/项目符号/
  字体字号），文件读写接 VFS，内容以 HTML 存 `contents`
- 工具栏用文字标签而非图标：手上没有写字板工具栏对应位图，
  套用 `ui/nav/` 的导航图标会比文字更失真

### 校验脚本的两个坑（都已修）
1. **展开语法误报**：`...target` 前面是点号，会被
   `(?<![\w.$])name(?![\w$])` 的边界正则漏算，导致"未使用声明"误报。
   修法：计数前先把源码里的 `...` 替换成空格再匹配。
2. **eslint-disable 的反噬**：用 `[]` 空依赖 + `eslint-disable-next-line
   react-hooks/exhaustive-deps` 来只跑一次 effect 是危险写法——
   若规则未触发，会报"未使用的 disable directive"，
   而 CI 下告警即错误。正确做法是**用 ref 守卫** + 写完整依赖列表。

## 补应用的「数据可得性」筛选原则（重要，避免走弯路）

补应用前先问一句：**这个应用要显示的数据，我手上有没有真实的？**

| 应用 | 数据来源 | 结论 |
|---|---|---|
| 命令提示符 | VFS 真实文件树 | ✅ 已做 |
| 音量控制 | prefs 真实状态 | ✅ 已做 |
| 计算器 | 纯计算 | ✅ 已做 |
| 写字板 | VFS 文本内容 | ✅ 已做 |
| 字符映射表 | Unicode 码位（标准数据） | ✅ 已做 |
| **磁盘清理** | 需目录体积 | ❌ **放弃**：VFS 整盘文本仅 6762 字符，无体积字段 |
| **系统信息** | 需 CPU/BIOS/内存等硬件信息 | ⚠️ 只能编造硬件参数，需谨慎（可只展示真实项：屏幕分辨率、UA、时区、主题、VFS 统计） |
| 图片查看器 | 需图片二进制 | ⚠️ VFS 只存文本，需先设计图片存储方式 |
